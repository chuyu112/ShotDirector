# 镜导（ShotDirector）产品需求文档 PRD

文档版本：V1.0（2026-08-07）  
产品形态：本地优先的 AI 导演、漫画转分镜与逐镜审核工作台  
目标用户：AI 影视导演、分镜师、编剧、提示词设计师、制片与个人创作者

## 1. 产品愿景

把“漫画/脚本 → 可执行分镜 → 资产 → 白模 → 生图 → 视频提示词 → 审批”变成一条证据可追踪、修改可传播、结果可恢复的导演工作流。

产品的关键价值不是替用户一次生成大量文字，而是确保：

- 不丢原作事实和细节。
- 不把不同日期、地点、人物或事件混在同一镜头。
- 全局设定只改一次，相关镜头自动同步。
- 单镜修改只影响正确的镜头和资产。
- 每项修改可以反推到源脚本，但不会未经批准自动盖章。
- 提示词、白模和布局图真正帮助视频生成，而不是制造更多冲突。

## 2. 背景与核心问题

现有 AI 视频工作流常见问题：

1. 一次生成几十个镜头，用户难以完整审核，错误直接进入视频生成。
2. 人物发型、服装、关键道具、车辆方向和空间关系在不同镜头漂移。
3. 批注处理慢，且“页面已改”“源文件已改”“提示词已改”经常不是同一状态。
4. 漫画 OCR、画格和镜头被机械映射，导致不同剧情或角色串镜。
5. 生图提示词照抄视频提示词，文字过长，静态模型抓不住重点。
6. 白模关节、姿势、车头方向、机位和运镜表达不够清楚。
7. 生图等待阻塞后续审核。
8. 删除草稿只清 UI，不清磁盘，旧数据可能污染新项目。

## 3. 产品原则

### 3.1 证据优先

原脚本文字、漫画页、漫画分格截图、对白和事实是“证据层”；导演运镜、时长、动作细化和提示词是“创作层”。两层分开保存，创作不能覆盖证据。

### 3.2 稳定身份

Shot、人物、道具、场景、分格和生成结果使用不可变 UID。用户看到的 `SHOT 01` 只是显示序号，可以整体平移或重排，不能作为数据库主键。

### 3.3 修改传播可见

修改全局人物设定后，系统显示哪些 Shot、资产和提示词受影响。用户确认传播后再批量更新；任何失败都要显示在具体对象上。

### 3.4 审批独立

批注、自动优化、源文件回写、出图和选图都不等于审批。只有单独签字盖章才使 Shot 进入“已批准”。

### 3.5 异步不阻塞

GPT、LibTV 和视频拉片都是后台任务。用户可继续编辑和审核其他 Shot；同一资源的冲突任务由版本号和幂等键拦截。

### 3.6 风格分层

最终视频美术风格、临时分镜图风格、3D 白模材质完全分离。临时赛璐璐分镜和白模不能污染最终真人电影化提示词。

## 4. 范围

### 4.1 本期范围

- 项目与全局设定。
- 脚本载入与逐镜审核。
- 漫画批量上传、分格、文字/剧情/动作提取和 Shot 草稿生成。
- 人物、关键物品、场景资产自动识别与同步。
- TOP VIEW 与 3D 白模导演布局。
- LibTV、手动上传、GPT Image Generation 三种参考图来源。
- Seedance 2.0 / 2.5 提示词与参考包。
- 单镜盖章、版本、脏数据和源文件反推。
- 后台任务状态、失败恢复和项目级删除。
- 本地项目包导入/导出。

### 4.2 暂不作为核心范围

- 完整非线性剪辑器。
- 在线多人协同和云端权限系统。
- 自动发布成片。
- A-ROLL / B-ROLL 强制分类；未来可作为可选标签。
- 取代专业 DCC 的完整角色绑定和动画系统。

## 5. 核心对象模型

| 对象 | 关键字段 | 说明 |
| --- | --- | --- |
| Project | `projectUid`, title, background, finalArtStyle, modelProfile | 一个剧集或漫画项目的独立命名空间 |
| GlobalSetting | characters, props, locations, timeline, continuity, prohibitions | 项目事实源 |
| SourceDocument | type, fileName, hash, pages, text | 脚本或漫画原始来源 |
| SourcePanel | `panelUid`, page, bounds, crop, OCR, include | 漫画证据单元 |
| Shot | `shotUid`, displayNumber, title, duration, fields, status | 可独立审核与生成的镜头 |
| Subshot | suffix, timeRange, blocking, actionBeat | 同地点同时间的连续机位/动作分段 |
| Asset | `assetUid`, type, name, description, referencePolicy | 人物、场景、关键道具 |
| ShotAsset | shotUid, assetUid, role, priority, enabled | 镜头和资产的多对多关系 |
| DirectorView | topView, whitebox, camera, trajectories | 人看和模型看的空间约束 |
| PromptPackage | kind, sourceVersion, prompt, negatives, refs | 静态生图或视频提示词包 |
| ReviewEvent | actor, action, before, after, timestamp | 修改、回写、盖章和撤销轨迹 |
| Job | type, status, progress, inputs, outputs, error | GPT/生图/拉片后台任务 |

关键约束：

- `shotUid` 永不因插入、删除或重新编号改变。
- `displayNumber` 可整体重排。
- 所有生成结果必须记录 `sourceVersion`。
- 每个 Shot 必须知道来自哪些 `SourcePanel` 或原文片段。
- 删除 Project 时按 manifest 精确级联，禁止用模糊目录或标题匹配。

## 6. 信息架构

顶部主导航：

1. 项目/载入。
2. 全局设定。
3. 漫画转分镜 / 视频拉片。
4. Shot 进度条。
5. 资产同步。

单 Shot 内三步：

1. 脚本。
2. 出图。
3. 确认。

脚本页统一显示：

- 人物。
- 物品和场景。
- 剧情。
- 动作。
- 连续性。
- 最终视频美术风格。
- 对白/声音。
- 原文与漫画画格证据。
- DIRECTOR VIEW 独立批注。
- 静态参考图提示词。
- 视频生成提示词。

## 7. 详细功能需求

### FR-01 项目与全局设定（P0）

1. 用户可新建、载入、另存、导入和导出项目。
2. 项目首页显示项目名、故事背景、最终美术风格、目标模型、Shot 数和批准进度。
3. 全局设定独立于 Shot 批注，拥有独立“发送全局批注”和保存按钮。
4. 人物设定包括身份、年龄段、面部、发型、体型、服装、表演基调、禁止变化。
5. 场景设定包括年代、地点、空间结构、天气、光线、可变与不可变元素。
6. 道具设定包括外观、尺寸、状态、持有人、出现区间和是否占全能参考位。
7. 修改全局设定后列出受影响对象；用户可全部应用或逐项排除。
8. 保存失败时保留编辑内容并显示明确错误，不能显示“已保存”。

验收：修改任意人物的全局发型规则后，所有引用该人物的 Shot 与提示词进入“待同步”；被全局禁止的道具不能继续出现在后续生成结果中。

### FR-02 脚本载入（P0）

1. 支持 JSON、Markdown、TXT 和自然语言。
2. 显示脚本名称，建立独立项目命名空间。
3. 结构化导入保留原始文件、hash 和全文，不覆盖原件。
4. GPT 只负责整理结构，不能擅自改变关键剧情事实。
5. 导入前提供预览：镜头数、总时长、缺失字段、重复编号和模型限制。
6. 用户确认后一次提交；失败不产生半成品草稿。

### FR-03 漫画转分镜（P0）

输入：最多 40 张 PNG/JPG/WebP，可设日漫右到左或左到右。

流程：

1. 文件名自然排序，允许拖动重排。
2. 判断单页、双页、装订中缝、跨页格、封面、纯插画、留白和作者后记。
3. 为每个画格生成稳定 `panelUid`、百分比边界和裁剪图。
4. 在原页叠加黄色剧情格、灰色排除格，用户可更改范围和是否纳入。
5. OCR 提取对白、旁白、音效；低置信内容标“疑似”。
6. 识别人物、场景、关键物品、剧情、动作、表情和视线关系。
7. 根据地点、时间、摄影机意图和连续动作合并/拆分 Shot。
8. 给出建议运镜、时长、转场和声音，但与漫画事实分栏显示。
9. 自动生成资产项和提示词。
10. 进入逐镜审核时创建全新独立草稿；绝不复用其他剧集的 Shot ID 或资产。

Shot 自动生成必须包含：

- 标题与时间范围。
- 剧情起点—动作—结果。
- 人物及身份关系。
- 物品和场景。
- 台词与说话者。
- 表情、情绪、心理和视线。
- 动作节拍与最低可执行时长。
- 摄影机景别、机位、运镜和焦点变化。
- 连续性与禁止项。
- `sourcePanels` 与可见的分格截图。
- 人物/场景/关键道具全能参考候选。
- 静态参考图提示词和视频提示词初稿。

验收：点击任意 Shot 时必须看到对应的漫画裁剪图；人物、台词和道具不能来自别的画格。重新编号不改变证据和资产关系。

### FR-04 视频拉片（P1）

1. 支持 MP4、MOV、MKV、WebM、M4V、AVI。
2. 每秒至少抽一帧，生成时间码、接触表和媒体信息。
3. 分析剧情、构图、运镜、剪辑、表演、连续性和声音。
4. 不可靠对白不补写。
5. 输出可下载 JSON、Markdown 和可转 Shot 草稿。

### FR-05 逐镜脚本审核（P0）

1. Shot 字段在同一页完成审核。
2. 支持直接编辑、字段批注、Shot 批注和全片批改。
3. 用户可同时编辑多个 Shot，不需要强制逐个提交批注。
4. 全片批改按小批次并行；失败批次可单独重试。
5. 修改前后快照、字段变化和 GPT 解释进入版本轨迹。
6. 每次写回源文件后立即重新编译受影响提示词。
7. 批注链路超时不丢用户输入。

### FR-06 审批盖章（P0）

1. 每个 Shot 独立盖章。
2. 没有批注也可盖章；“没有需要修改”是合法审核结果。
3. 批注上传、GPT 修改、出图、选图均不自动批准。
4. 上游关键字段变化后，已批准 Shot 标为“批准已过期”，需要重新确认。
5. 盖章记录用户、时间、源版本和提示词版本。

### FR-07 DIRECTOR VIEW / TOP VIEW（P0）

1. 明确画出道路、建筑、人行道、人物、车辆和关键道具。
2. 车辆用形状表达真实车头/车尾，不用“车头”两个字代替。
3. 行驶轨迹箭头画在线路末端，不覆盖车辆。
4. 不同机位用不同颜色虚线；摄影机朝向和运镜轨迹独立表达。
5. 提供“显示名字、显示动作、显示注释”三个独立筛选器。
6. 小字默认可隐藏，人物名字默认保留。
7. 一个 Shot 有 A/B/C/D 子段时，每段拥有可切换的独立 DIRECTOR VIEW。
8. 跨时间或跨地点必须拆成新 Shot；同地点同时间的连续动作可用子段。

### FR-08 3D 白模（P0）

1. 默认使用统一的细腻人形，而非方块堆砌。
2. 肩、肘、腕、髋、膝、踝使用平滑关节连接；默认没有夸张嘴部。
3. 提供站立、坐姿、行走、跑、回头、举右手、单手持枪、双手持枪、拉拽、挣扎、倒地等姿势库。
4. 可直接拖动人物、物体和摄影机；数字坐标是精调入口，不是唯一移动方式。
5. 支持旋转、缩放、地面对齐、吸附和撤销/重做。
6. 坐姿必须满足臀部落座、膝盖自然弯曲、脚落地，避免腿撅到身后。
7. 摄影机支持位置、目标、FOV、构图安全区和运镜路径。
8. 输出 2048×1152 干净白模 PNG：无文字、箭头、网格、最终人脸和服装。

### FR-09 资产同步（P0）

1. 自动识别人、关键物品和场景；默认加入全能参考候选。
2. 普通物品可自动降级为文字约束，不占参考位。
3. 每个资产支持三种来源：LibTV CLI 生图、GPT Image Generation、手动上传。
4. LibTV 常用模型：Lib Image、General image Pro，可选 Seedream 5.0 Pro；模型列表以 CLI 实际能力为准。
5. 支持常见画幅，包括 16:9、9:16 和其他模型支持尺寸；默认 2K，可选择质量和数量。
6. 上传图片自适应横竖屏，完整显示，不强裁主体。
7. 全局资产修改后，Shot 引用和提示词同步进入待更新。
8. 显示 Seedance 全能参考计数和每项占位原因。

### FR-10 静态参考图提示词（P0）

目的：生成导演可读的临时参考图，锁定剧情、场景、站位和动作。

编译顺序：

1. 当前 Shot 的核心画面目标。
2. 人物身份、表情、视线和关键动作。
3. 场景与空间关系。
4. 摄影机和构图。
5. 关键连续性。
6. 少量高价值禁止项。
7. 临时分镜画法。

要求：

- 不照抄整份视频提示词。
- 默认提供可编辑文本框和恢复默认。
- 对多小格分镜明确每格的时间、画面和必须出现项。
- 删除重复描述和模型无法执行的流程性文字。
- 不生成对白气泡、水印或乱码文字。

### FR-11 视频提示词（P0）

1. 严格使用最终视频美术风格。
2. 包含时间轴、动作持续时间、视线、表演、摄影、声音和连续性。
3. 台词使用目标语言；中文只做备注，不要求画面生成字幕。
4. 支持“只要音效、不要 BGM”等声音规则。
5. 强调活人感：听者反应、呼吸、吞咽、迟疑、疼痛反馈、重力和动作惯性。
6. 视线必须有明确对象；人物不能各说各话。
7. 危险动作必须可执行，例如拔枪、握枪、开枪、受击和倒地有自然阶段。
8. 不必要时不把枪口对向摄影机，避免产生错误叙事含义。

### FR-12 后台任务与恢复（P0）

1. 显示 received、preparing、running、validating、writing、completed/failed 等真实阶段。
2. 显示任务编号、开始时间、更新时间和耗时。
3. 网络断开后自动恢复查询，但不能重复提交计费任务。
4. 使用幂等键：项目 UID + Shot UID + 源版本 + 任务类型。
5. LibTV 生图与 GPT 批注使用独立队列。
6. 用户离开当前 Shot 后，完成结果仍回填到正确 Shot。
7. 失败结果保留可读错误和恢复入口。

### FR-13 数据删除与草稿管理（P0）

1. “清空队列”只清未上传选择；“删除草稿”清浏览器草稿；“删除项目及全部数据”级联清理服务器文件，三个动作名称不得混淆。
2. 删除前显示准确范围：项目、Shot 数、上传素材、分格、生成图、白模、任务和源回写文件。
3. 用户输入项目名或再次确认后执行。
4. 服务端根据 Project Manifest 精确删除，拒绝根目录、通配符和越界路径。
5. 返回逐项删除结果；失败项可重试。
6. 原始外部素材默认不删除，除非用户单独明确授权。
7. 提供“导出后删除”。

验收：删除旧漫画项目后，刷新浏览器、重启桥接并重新打开页面，旧 Shot、任务、上传副本、分格和生成图均不会出现；用户 Pictures/Desktop 原件保持不变。

### FR-14 项目包导入/导出（P0）

项目包至少包含：

- `manifest.json`。
- 全局设定。
- Shot 数据与审核轨迹。
- 原文/画格证据。
- 资产元数据与可选二进制文件。
- TOP VIEW、白模和生成图。
- 静态图/视频提示词及源版本。
- 任务摘要，不含账号令牌。

导入时校验版本、hash、UID 冲突和文件完整性，并允许“作为新项目导入”。

## 8. 状态机

Shot 建议状态：

```text
草稿 → 待审核 → 已修改待确认 → 已盖章
                    ↓
                 上游已变化
                    ↓
                 批准已过期
```

生图状态与审批状态正交：

```text
未生成 → 生成中 → 有候选 → 已选图
              ↘ 失败/可重试
```

资产状态：

```text
待创建 → 生成/上传中 → 可用 → 已锁定
                         ↓
                    上游变化待同步
```

## 9. 非功能需求

### 9.1 性能

- 首屏可交互目标小于 3 秒（不含首次 npm 编译）。
- Three.js 和媒体实验室按需加载。
- 100 个 Shot 的导航和编辑保持流畅。
- 本地字段修改 100 ms 内反映到依赖状态。

### 9.2 可靠性

- 所有写入采用临时文件 + 原子替换。
- 每个后台任务可恢复且幂等。
- 导入失败不创建半成品。
- 源文件、浏览器状态和任务结果保存版本号。

### 9.3 安全与隐私

- 桥接只监听回环地址。
- 每次启动使用随机配对令牌。
- 不在项目包、日志和前端状态中保存 LibTV/Codex 凭据。
- 文件读写必须限制在 manifest 列出的项目路径。
- 删除操作拒绝工作区根、用户目录和未解析变量。

### 9.4 可观察性

- 日志包含 requestId、projectUid、shotUid、任务类型和阶段。
- 不记录账号令牌和完整敏感提示词。
- UI 能打开对应任务的诊断摘要。

### 9.5 可访问性

- 核心操作可用键盘完成。
- 状态不只依赖颜色。
- 图片有名称、Shot 和来源说明。
- 横向滚动区域明确显示前后导航。

## 10. 成功指标

- 漫画导入后，随机抽查 20 个 Shot，证据图与剧情匹配率 ≥ 95%。
- 资产串镜、Shot ID 冲突为 0。
- 全局设定一次修改后，受影响提示词漏同步率 < 1%。
- 后台任务因刷新丢失结果的比例 < 1%。
- 用户完成一个 Shot 从审核到盖章的中位时间下降 40%。
- Seedance 首次生成出现角色/场景/关键道具硬冲突的比例持续下降。
- 项目删除后服务端残留检查通过率 100%。

## 12. 当前最优先验收场景

1. 新建一个完全空白的第三话项目。
2. 只上传一张漫画页。
3. 填写固定故事背景和“昭和 60 年日本真人电影化”最终风格。
4. 系统能从测试漫画中识别主要人物、关键场景和关键道具，并建立可编辑的全能参考候选。
5. 将两段连续内容保留为同一 Shot 下的两个内部子镜，而不是污染后续 Shot 编号。
6. 每个子镜显示自己的漫画裁剪证据。
7. 自动生成对白、视线、表演、动作、摄影、声音、全能参考和两套提示词。
8. 用户修改人物视线或中弹反馈后，源 Shot 和两套提示词同步更新。
9. 用户单独盖章，生图可在后台运行且不阻止审核下一 Shot。
10. 删除测试项目后，浏览器与服务器无残留，原漫画文件仍在。

这个场景通过后，再扩大到 12 页整批导入。
