# Shot 01 人工核对与结构同步（本地实现）

本批处理 [线上 Bug 复查](2026-09-11-线上Bug复查.md) 中的内容与证据一致性问题。交付的是可执行的人工核对流程；没有替用户裁定生产画格，没有改写生产草稿、部署、推送 GitHub 或提交付费模型任务。

## 使用流程

1. 在符合条件的 Shot 01 完整提示词区域点击「原裁图人工核对」。入口只接受已保存的 **26 秒、10 个不同来源画格、最后为 P02-R-G08**；具体画格与顺序始终读取当前 Shot，不能由格号推断，不能补回已移出的 G04。
2. 对照每张原始裁图填写可见事实、核对结论、原文情况和纠正依据，并逐格勾选。没有预选或模型代填。无文字与无法辨读分别记录；无法辨读时不能保存猜测台词，事实冲突未裁定则只能暂存。
3. 手动核对动作说明、内部节拍、必须呈现的内容、禁止项、连续性与全局时间线。原稿原样进入编辑区，系统只检查，不自动替换措辞或平均分配时长。可查看全部 Shot 的已保存时间码作为时间线核对依据。
4. 「检查变更预览」展示同步前后内容及全部人工结论。确认人填写姓名，勾选明确确认后才可执行「确认并同步结构」。变更预览与确认使用同一份内容哈希，预览后任何修改都需重新预览。
5. 同步后完整提示词保留，状态为需重新严格审核，旧批准撤销。提示词区域提供「人工核对与结构同步溯源」，可查原始识别、人工结论、同步前完整稿、Chat 旧稿和审核信息。后续正文再修改，仍由原有版本审核门槛阻止直接批准。

## 数据边界与实现

- `app/shot-content-review.mjs` 是不调用模型的共用校验与同步字段契约；`app/shot-content-review.tsx` 是独立人工核对界面，`server/shot-content-review.mjs` 负责版本检查、持久化和确认事务。主页面和桥接仅接入入口。
- 只更新当前 Shot 的 `action`、`segments`、`negative`、`continuity`，以及当前项目草稿的 `globalSettings.timeline`。追加 `shot.contentConfirmation` 与项目 `contentReviewHistory` 作为人工确认和审核溯源。26 秒、10 格、UID、来源 ID、顺序和时间码保持原有值；不改剧情、对白、人物、画框、原始识别、其他 Shot 的正文或用户级全局文件。
- `segments` 必须无间隙、无重叠地覆盖 0–26 秒，并按当前原序覆盖全部 10 格，最终止于 G08。允许一个画格连续跨多个节拍，允许多个画格合成一段。来源 ID 与 `mustShow` 的其他事实约束分开编辑，确认时合并保留，避免把视觉要求当作无效 ID 删除。
- 对明确的旧 8 秒声明、旧终点及动作中的范围外画格发出阻断提示；普通内部 8 秒节拍和合法的 G04/G06 引用不作为整镜时长错误。检查只定位问题，最终事实由核对人裁定。
- 原裁图接口只读取已经存在的裁图与已提交分析，计算 SHA-256；不调用旧恢复/修复逻辑、不重裁、不生成图片。核对快照绑定原图字节、文字证据、几何数据、项目和稳定 Shot UID。
- 准备、保存草稿和预览都不改项目正文。确认时再次比较项目内容、全部原裁图和证据哈希；内容变化、缺图、事实待裁定、运行/排队/待恢复任务均阻止同步。
- 同一 Worker 中校验与原子草稿替换之间没有异步间隙。旧快照保留在 `work/shot-content-reviews/<id>.json`，项目内也保存变更前的 reviews、时间线和人工结论。确认接口可按同一记录与预览哈希重复查询结果，不重复应用；崩溃或丢失响应后可恢复同一次确认。
- 确认写入新的 `agentRevision`，沿用原有旧标签页防覆盖策略。全局时间线改变时，其他 Shot 正文、产物和报告原文保留，但旧审核与批准失效，防止继续使用依赖旧全局上下文的报告。
- Creator、Chat 和严格 Reviewer 读取已确认事实时，显式分开人工值与 `machineEvidence` 历史说法；记录原裁图哈希、确认人、时间和版本。新事实冲突只报告，不能自动改稿。已确认 Shot 的旧请求不能通过省略确认指针回退到旧模型证据；原图变化则需重新人工核对。
- 结构同步不调用生成、Chat、审核或视频接口。重新严格审核仍须用户在审核台主动提交，本批不执行该付费步骤。
