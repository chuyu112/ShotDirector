# 心流与 Kunpeng：优点采用方式

2026-09-09 用户明确：把心流和 Kunpeng 的闪光点拿出来用于漫镜，不用单独写插件。

采用方向是**按能力融入漫镜现有工作流**。两个源码附件作为溯源、参考和验证资料保留；不以完整搬入两套产品、增加独立插件、另一套服务或第二个工作台为交付目标。

## 心流值得采用的部分

| 可复用点 | 对漫镜的价值 | 采用位置与边界 |
| --- | --- | --- |
| 按叙事节拍整理分镜 | 把动作、问答、反应、停顿、线索与结果拆清，检查原文覆盖 | 增强现有脚本导入与导演配方；同一个 Shot 内使用 `segments` 表达必要节拍。最终 Shot 分组由漫镜规则及用户确认决定，不照搬“一句一镜”或原包技术分段。 |
| 人物、场景和道具的可见描述 | 把抽象评价转为外形、位置、材质、动作、表情等可拍摄信息 | 增强现有全局人物档案、资产提取与提示词；先消歧同一人物和称谓，分开来源观察与创作建议。原作无法确认的信息明确标注，不能当成证据。 |
| 统一视觉规则 | 在跨 Shot 的色彩、光源、材质、空间和冲突表现上保持连续 | 融入现有全局设定与完整提示词，沿用最终成片风格、临时分镜风格、白模材质的分层。 |
| 提示词方法与反馈偏好 | 将可读的导演规则用于持续创作，而不是重复手填 | 从 Gem 中提炼可选导演方法，进入漫镜既有上下文与任务快照；已确认全局规则和原作证据保持优先。 |
| 长篇缩写和续写问答 | 便于理解长篇结构、探索创作分支 | 作为小说工作流的按需能力；缩写保留原文索引，续写单独保存为创作候选。只有用户明确选择创作模式时才扩写，不能覆盖原作。 |

来源：[心流附件](../attachments/xinliu/README.md)、[原包 Gem](../attachments/xinliu/gems.json)。优先研究原包 `createModelExtraction`、`createModelSummary`、`createModelLineStoryboardV2Segment`、`createModelVisualRules` 的任务组织方式，并结合已有审阅结论筛选。

## Kunpeng 值得采用的部分

| 可复用点 | 对漫镜的价值 | 采用位置与边界 |
| --- | --- | --- |
| 稳定 ID、人工锁定与状态验证 | 让 Agent 修改可定位、可核对，保留用户确认内容 | 漫镜已有对应工程契约，继续使用既有实现；新增能力须接入它。 |
| 原子快照与可撤销修改 | 保留修改历史，降低状态被旧任务覆盖的风险 | 漫镜已有 Harness 账本和状态版本机制；新增状态沿用相同归属与历史语义。 |
| 运镜分类与模板 | 区分固定、推拉、横移、摇摄、升降、环绕、跟拍等不同意图 | 按需要补充漫镜现有导演方法与白模摄影机能力；区分摄影机位置、注视点和视场角，明确起止状态与叙事目的。参数由当前场景决定，不照搬固定移动距离。 |
| 人物动作路径和关键帧 | 让人物走位、动作起止与摄影机衔接更可控 | 增强现有白模数据及编辑器；对象与 Shot 使用稳定映射，路径、姿态和摄影机独立描述。新数据需支持保存、恢复、撤销与人工锁定。 |
| 预演检查与产物关联 | 让机位、空间和动作先经过可视化复核 | 预演结果绑定当前 Shot 和版本，继续进入漫镜既有参考图、提示词与人工确认链路。 |

来源：[Kunpeng 附件及许可证](../attachments/kunpeng/README.md)。重点参考原包 `packages/core/src/cameraTemplates.ts`、`pathCurve.ts`、`types.ts` 与 `packages/mcp-server/src/repository.ts`；上游插件层只作为源码资料保留。

- [脚本与提示词任务](../scripts/shotdirector-bridge.mjs)：已有脚本导入、资产分析、完整提示词和独立审核链路。

## 当前状态

本次更新的是采用方向和可复用点清单，没有新增运行时功能。稳定 ID、人工锁定、状态验证及历史快照已有漫镜实现；其他条目是结合当前代码选出的增强方向，不表示已经上线。

后续按实际制作需要逐项实现、验证并记录。优先改善现有分镜/资产/提示词质量，再按白模使用需求补充运镜与动作编排；不另建插件或独立工作台。
