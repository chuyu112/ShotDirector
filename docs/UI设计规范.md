# 漫镜 UI 设计规范

## 定位与边界

漫镜是把漫画转为分镜提示词、再生成 AI 视频的制作工具。界面以清楚、可读、可操作为优先，不使用营销页面式的大幅装饰、渐变或重复强主按钮。

主链路为：漫画入库 → 拆分编组 → 分镜 → 完整提示词 → 独立审核 → 用户确认 → AI 视频。样式优化不改变 Shot 分组、阅读顺序、裁框、模型路由或批准规则。

## 公共视觉

公共主题集中在 `app/workbench.css`，由 `app/layout.tsx` 在 `app/globals.css` 之后加载。旧文件保留组件布局；新增公共外观优先使用主题变量和明确的组件选择器，避免用 `header span` 等宽泛规则覆盖品牌、状态或正文。

| 项目 | 当前基准 |
| --- | --- |
| 页面底色 | `--paper: #f4f3ef` |
| 工作面板 | `--panel: #fffefb`；输入区域以白色为主 |
| 主文字 / 辅助文字 | `--ink: #20211f` / `--muted: #686a64` |
| 分割线 | `--line: #ddded7`；控件边界使用 `--line-strong` |
| 字体基准 | 正文 14px、辅助信息 12px、标签 11px |
| 控件 / 面板圆角 | 6px / 8px |
| 常规按钮 | 最小高度 40px；主生成操作不小于 44px |
| 顶栏三组控件 | 同宽、同高 64px |
| 页面侧边距 | 16–32px，自适应屏幕 |

标题按内容层级使用约 20–30px；正文行高约 1.6–1.85。字体基准不是强制所有编号、标题等大，避免将密集说明压成 7–9px。常用字重采用中等或半粗体，少用整段极粗文字。

### 颜色语义

- 蓝色：当前选择、主要操作、键盘焦点与进行中的任务。
- 绿色：明确成功、确认或批准；“生成了讨论稿”不等于人工批准。
- 黄色：人工黄框、选中画格、需注意或已过期的内容。
- 红色：真实错误、阻断问题、删除等危险操作。
- 中性色：说明、配置状态、未测试与未生成，不用警告色制造无故告警。

状态不能只靠颜色表达，须同时保留文字。禁用按钮保持可辨认，并在附近说明为什么不可操作。主操作使用统一蓝色，不再因所在页面不同混用橙色、绿色按钮。

提示词任务提交后须立即显示醒目的“正在生成提示词”；排队和断线恢复须明确区分。提示词面板、对应 Shot 按钮与底部状态同步显示，生成中不能只将按钮变灰或继续显示“等待盖章”。本次模型读取任务绑定的模型，不随顶部模型选择改变；不显示虚构百分比或推理内容。

严格审核提交后在审核内容上方显示“严格审核中”的蓝色状态框与加载动画；排队显示“严格审核排队中”，断线显示“正在恢复审核任务状态”。拿到当前版本的完整报告后，显示绿色勾选与“严格审核完成”，同时展示完成时间、发现的问题和人工确认要求。完成提示不能仅依据模型的最近调用成功记录；旧报告明确标记为上一版／需重审。审核按钮、Shot 导航、创作台审核入口与底部状态同步提示。本次审核模型按项目与 Shot 对应的任务显示。

工作中的提示使用独立字号：主标题桌面和 900px 为 24px、手机为 22px，状态文字和工作按钮至少 16px；用文字、加载标识与蓝色状态框共同表达。生成、审核、主力 Chat 选择采纳、分析、上传、恢复、保存和手动模型测试遵循同一规则，不能因 disabled 而变成难以辨认的小灰字。

主力 Agent 工作状态在 Chat、当前 Shot、导航、严格审核台和底部同步显示，优先于旧报告的完成提示。区分排队、讨论、核对审核意见、选择采纳和恢复任务；任务标签取本次提交消息，模型取任务绑定值。切换工作台不能停止原回合结果恢复；不确定的网络结果通过只读查询确认，不自动重复提交。完成改稿后保留旧稿、将旧报告标记需重审，不暗改人工批准状态。

## 页面职责

| 区域 | 主要职责 |
| --- | --- |
| 项目与顶栏 | 明确当前项目、工作台、Chat / Work 模型、推理深度与保存状态 |
| 漫画与画格编组 | 保留原图证据，展示归属、阅读位置、时长评估和人工编辑入口 |
| 提示词与 Shot Chat | 阅读当前讨论稿、查看真实模型及生成时间、按用户消息讨论与改稿 |
| 严格审核台 | 只读查看提交快照、选择独立 Reviewer、阅读问题与建议 |
| 全局设定 | 保存作品共用背景、风格、人物与约束；不与单话项目混为一层 |
| 脚本体检与资产 | 展示覆盖、依赖、可用状态与待处理问题 |
| 视频工作区 | 展示生成准备、结果与人工确认边界，不把占位内容当成产物 |

长文使用安静的阅读面板。模型来源、完成时间与生成中状态独立分层；生成新版本时保留上一版正文，并明确标识，不用切换下拉模型伪装历史稿来源。

## 布局与响应式

- 桌面版按“项目上下文 → 流程 → 当前 Shot → 内容”排列，减少重复大色块和重边框。
- 顶栏的工作台切换、模型、推理深度为三组等尺寸控件；窄屏整体换行，辅助描述可省略显示，但不能遮住主标签或控件。
- 创作台与严格审核台共用工作台切换组件与顶栏网格，切换按钮的坐标、宽高和两项顺序在同一视口下保持一致；审核台不因省略 Creator 控件和保存状态而将切换按钮推到右侧。
- 900px 及以下，制作流水线保持横向滚动，不展开成占满首屏的七行；审核和资产内容逐步改为单列。
- 700px 及以下，顶栏三组控件纵向排列，提示词操作与生成状态允许换行；当前 Shot 操作条不再占据固定悬浮位置。
- 长项目名、模型名、来源信息允许换行；表格、画格编组与多 Shot 导航在各自容器横向滚动，不撑宽整页。
- 浮层菜单保持在顶栏和当前 Shot 操作条上方，限制视口内高度并独立滚动；不以裁切菜单或缩小文字解决遮挡。
- 保留键盘可见焦点，尊重减少动态效果设置。

## 不可破坏的产品约束

- 漫画原图不镜像、不拉伸、不为适应 UI 改裁框坐标。黄框、裁图和阅读顺序继续遵循人工锁定与原图证据规则。
- 严格审核只提问题、证据、建议，不改稿、不批准。修改通过当前 Shot 的主力 Chat 执行；用户确认前不触发视频生成。
- Chat 保留 Enter 换行、Ctrl/Cmd+Enter 发送；聊天记录和候选稿按项目、Shot 隔离保存。
- 项目操作与全局文件操作分开；界面变化不能删除已保存数据或改变历史模型来源。
- “加载项目”必须先以用户选中的服务器项目为目标，加载后回到该项目入口并恢复最近工作区；不得沿用空白 `?main=1` 地址，也不得把空模板展示成已保存项目内容。
- **LLM 模型测试全部手动。** 只有点击“测试全部模型”或单模型“重测”才发起请求；加载、刷新、切换模型和失败不自动调用，轮询仅读取状态。
- 模型测试区分接口与格式结果；格式错误不代表接口不可用，配置就绪也不代表真实测试已通过。
- 未生成的站位、白模或视频必须明确为空态，不能用示例内容冒充生成结果。

## 验证与后续待审

本文件描述当前代码的视觉基准与维护约束，不表示已完成线上部署或真实项目端到端验收。

回归应覆盖桌面、中间宽度与手机：检查顶栏等尺寸、菜单层级、按钮禁用原因、长文换行、错误/过期区别及横向容器边界；同时确认没有新增模型调用或改变图像几何。

复杂 3D 白模的真实内容、长篇提示词和多 Shot 真实项目仍需人工确认实际观感与操作路径，不以静态样式预览替代验收。
