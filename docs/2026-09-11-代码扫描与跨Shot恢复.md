# 代码扫描与跨 Shot Chat 恢复

用户本轮明确要求扫描代码、推送 GitHub 并部署服务器；本轮授权包含发布当前经过验证的修复。生产内容仍由用户在原裁图核对流程中明确确认，不将部署视为画格事实确认或付费模型调用授权。

## 扫描与修复

- 纳入已有的工作状态放大、固定顶栏、审核结果恢复、人工内容核对和七项类型修复；审查身份隔离、原任务恢复、人工确认、版本失效与历史记录保留。
- 修复此前发现的跨 Shot Chat 恢复缺口：按项目、工作区、稳定 Shot UID、回合及来源版本，为全部待恢复 Chat 保留独立只读轮询。切换当前 Shot、刷新健康状态或另一个 Shot 加入不会重置已有查询。
- 每个回合只保留一个在途读取。原回合完成或移除、工作区切换、组件卸载时取消对应查询；晚到的旧结果不能回写或重启轮询。网络不确定时继续查原任务，不重发付费请求。
- 浏览器验收发现定时器以实例方法调用时触发 `Illegal invocation`，已用保留原调用环境的包装函数修正，并重新完成真实 React 页面的切 Shot 验收。
- Docker 构建上下文排除 `exports/`，与现有 `attachments/` 和私密环境文件隔离一致。

## 验证

- 定向回归覆盖跨 Shot 恢复、健康更新期间的慢查询、新增并行回合、完成后的独立清理、传输失败及工作区切换后的晚到结果。
- 隔离 UI 验收实际发送一次测试消息，模拟 POST 504、服务端延迟 20 秒与读取延迟 800 毫秒，立即切到 Shot 02。停留在 Shot 02 时，Shot 01 的 pending 清除、完整稿更新并保存一条回复，Shot 02 正文和聊天不变。回到 Shot 01 可见回复、旧稿保留及重新严格审核提示。没有真实模型调用。
- 浏览器定时器修正后，最终 `npm test` 类型检查、构建和 291 项测试通过，0 失败、0 跳过；lint 与 `git diff --check` 通过。原有七项类型错误已修复。
- 公开提交范围为应用代码、测试及项目文档。提交候选未发现本项目已配置密钥或私钥块；私密配置、原裁图、导出文件和参考源码附件保留在本地。

## 内容问题的边界

本批提供可执行的逐格人工核对与结构同步入口。实际生产 Shot 01 的十格事实仍需用户确认，26 秒与旧 8 秒描述也需要通过该流程完成核对和同步；不能把核对入口上线说成生产内容已经纠正。修改后的提示词仍需新的严格审核和人工批准。
