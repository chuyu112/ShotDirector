# 漫镜服务器版部署

服务器版把原来的单机导演台拆成三层：响应式 Web 页面、公开认证网关、按用户和项目隔离的漫镜 Worker。桌面浏览器与手机浏览器使用同一账户、同一项目和同一 API；当前交付是手机 Web 端，不是 iOS/Android 原生安装包。

## 已实现边界

- 邮箱注册、登录、退出和 30 天会话；密码使用 scrypt，数据库只保存会话 Token 的 SHA-256。
- SQLite WAL 持久化 `users`、`projects`、`sessions` 和 `resource_owners`。
- 每个用户注册时创建默认项目；顶部账户栏可新建、切换项目。每个用户／项目运行在独立目录和独立 Bridge 进程中，素材、任务结果、Harness 账本、源文件副本、LibTV 配置都不共用。
- 浏览器草稿、素材实验室状态和 IndexedDB 图片以 `userId + projectId` 命名空间隔离；切换账户会清空本会话缓存，切换项目则保留但不串读。
- 文字创作密钥只存在于 Gateway/Worker 的服务端环境。Creator 提供 GLM-5.3-Flash、Kimi K3、DeepSeek V4 Flash/Pro、Seed 2.1 Pro 与五个 JK API 模型；Reviewer 独立提供 Kimi K3、GLM 5.3、JK GPT-5.6 Sol、JK Gemini 3.8 Flash、JK Claude Opus 5。URL、Key、模型 ID 均由 env 读取，配置完整后才可选择。GPT 资产图仍使用独立配置与额度。
- 页面提供独立“创作台 / 严格审核台”。严格审核台只读画格与完整提示词，仅能重审并输出问题、证据和建议；没有编辑、应用、生成或批准入口。
- LibTV CLI 在 Linux Worker 中无头运行。账号使用手机号加短信验证码的两步登录；同一租户／项目命令 FIFO 串行，带 `--run` 的付费命令一直等待 CLI 进程终态，不增加后台轮询或超时重提。
- 同一套页面在 `768px` 以下切换为手机单列、触控按钮和横向阶段导航；漫画放大审阅和完整提示词栏也会改为手机纵向布局。站点提供 Web App Manifest，可从手机浏览器添加到主屏幕。
- 服务端持久化记录每用户每日 AI 模型调用预算、LibTV 付费提交、LibTV 登录和上传请求额度；项目数、单用户活跃 Worker 数、全站 Worker 数均有上限，空闲 Worker 会在新需求到来时安全回收。
- 本地模式仍可运行：没有配置 `NEXT_PUBLIC_MANJING_API_BASE` 时，页面继续连接 `127.0.0.1:4317`，不强制注册。

文字任务首次按 `MANJING_AI_PROVIDER` 路由，接受模型目录中的公开 ID；旧的 `glm`、`kimi`、`openai` 别名仅用于兼容。用户可在顶部菜单切换到另一个已完整配置的模型，选择原子保存到当前项目的 `work/writing-model-selection.json`，并在后续请求中真实生效。当前项目有任何写作、素材、出图或 LibTV 登录任务时都禁止切换，避免运行态不一致。每次调用结果旁会保存 usage sidecar。GPT Image 2 仍是独立、可选的服务端资产图能力，只有配置图片密钥并放开图片额度后才启用。

漫画 Box-to-Box 裁框可单独设置 `MANJING_MANGA_CROP_MODEL`，默认使用 `glm-5.3-flash` API。裁框固定使用 `low` 推理档位，不读取本机 Codex 登录，也不消耗 ChatGPT 账户额度。

GLM 使用 `max_tokens`，Kimi 使用官方建议的 `max_completion_tokens`；两者默认均为 16384，分别可用 `MANJING_GLM_MAX_OUTPUT_TOKENS` 和 `MANJING_KIMI_MAX_OUTPUT_TOKENS` 调整。达到上限的截断响应会被当作失败，不会保存成完整结果。Kimi 的限速会按请求中的该上限估算，所以不建议无条件调到最大值。

GLM-5.3 与 GLM-5.3-Flash 必须保持 `thinking.type=enabled`。推理档位只发送 `low`、`high` 或 `max`，不得发送 `medium` 或 `disabled`。页面中的一般创作推理深度按项目保存；漫画拆图固定为 `low`，每个 Shot 的完整提示词生成和严格审核固定为 `max`，并由 Worker 服务端覆盖，不能由浏览器降档。

## Docker Compose（推荐）

要求：Docker Engine、Compose v2、可访问 OpenAI 与 LibTV 服务的服务器，以及已解析到该服务器的域名。

```bash
cp .env.server.example .env.server
# 编辑 .env.server，至少填 MANJING_ALLOWED_ORIGINS，并完整配置 MANJING_AI_PROVIDER 所选模型的 URL、Key、模型 ID
docker compose --env-file .env.server -f docker-compose.server.yml build
docker compose --env-file .env.server -f docker-compose.server.yml up -d
```

默认由 Nginx 在 `8088` 提供站点；可用 `MANJING_HTTP_PORT` 调整。生产环境应让云负载均衡、Caddy 或另一层 Nginx 在外部终止 HTTPS，再转发到这个端口。公网环境必须保持：

```dotenv
MANJING_COOKIE_SECURE=true
MANJING_ALLOWED_ORIGINS=https://你的域名
MANJING_TRUST_PROXY=true
```

如果只在服务器本机用 HTTP 联调，才可临时把 `MANJING_COOKIE_SECURE` 设为 `false`。

Docker 构建默认固定 LibTV CLI `1.1.3`，对 Linux `amd64` 和 `arm64` 官方 zip 分别执行 SHA-256 校验，不执行远程 latest 脚本。升级时必须同时更新 `LIBTV_VERSION`、两个架构的 SHA 和对应 CLI 文档；离线镜像可传 `INSTALL_LIBTV=0`，再自行把经过校验的 `libtv` 放进镜像的 `/usr/local/bin/libtv`。

Worker 健康状态会实际执行 `libtv --version`，并把解析到的版本号放在 `libtv.version`；仅有二进制文件存在、但无法运行或输出无效时，会报告为不可用。

## 直接运行

```bash
npm ci
npm run build:server
cp .env.server.example .env.server
# 默认补入 MANJING_GLM_API_KEY；不要把真实密钥写回示例或提交到 Git
npm run start:web
npm run start:gateway
```

Web 默认监听 `3000`，Gateway 默认监听 `8080`。反向代理需要把 `/api/` 去掉前缀后转发到 Gateway，其余请求转发到 Web；完整示例见 `deploy/nginx.manjing.conf`。
服务器发布包必须使用 `npm run build:server`：它会将浏览器 API 固定为同域 `/api`，并在构建后拒绝任何仍包含本机 Bridge 地址的产物。systemd 发布脚本会在停止线上服务前再做一次相同校验。

### Alibaba Cloud Linux / systemd

目标机无法稳定访问 Docker Hub 时，可直接使用项目内的 systemd 单元。模板按 `/opt/manjing` 应用目录、`/var/lib/manjing` 数据目录、Web `127.0.0.1:3300` 和 Gateway `127.0.0.1:8180` 编写：

```bash
install -o root -g root -m 0644 deploy/manjing-web.service /etc/systemd/system/manjing-web.service
install -o root -g root -m 0644 deploy/manjing-gateway.service /etc/systemd/system/manjing-gateway.service
install -o root -g root -m 0644 deploy/nginx.manjing.systemd.conf /etc/nginx/conf.d/manjing.conf
systemctl daemon-reload
systemctl enable --now manjing-web manjing-gateway nginx
```

`manjing` 系统用户对 `/opt/manjing` 只读，只对 `/var/lib/manjing` 可写；`.env.server` 应为 `root:manjing 0640`，数据目录应为 `manjing:manjing 0700`。Nginx systemd 模板只服务 `kakayiduo.cloud`，80 端口只保留 ACME 校验并跳转到 443；部署前必须先签发证书，并保持 Secure Cookie。旧域名下线事实仅保留在历史记录 Markdown 中，不再出现在运行配置。

Alibaba Cloud Linux 3 默认软件源没有 FFmpeg。x86_64 目标可用已固定 wheel 和双重 SHA-256 校验的安装器：

```bash
sudo deploy/install-ffmpeg-static.sh /usr/local/bin/ffmpeg
```

该脚本安装带 `drawtext` 的静态 FFmpeg 4.2.2。视频拆帧脚本同时兼容服务器自带的 Python 3.6，并会自动选择 Linux／macOS／Windows 字体。

## 数据目录

默认根目录由 `MANJING_DATA_ROOT` 指定：

```text
/data/
├── auth.sqlite
├── auth.sqlite-wal
└── tenants/<userId>/projects/<projectId>/
    ├── project-source/
    ├── work/manjing-harness/
    ├── work/shotdirector-media/
    ├── work/shotdirector-responses/
    ├── work/shotdirector-artwork/
    ├── work/writing-model-selection.json
    ├── work/bridge-shutdown-state.json
    └── libtv-server/
```

备份时停止 Gateway，或用 SQLite 在线备份工具一致地备份数据库，同时保存整个 `tenants/`。不要只备份数据库：素材、裁图、Harness checkpoint 和 LibTV 登录状态都在项目目录。

## 运营检查

```bash
curl -fsS http://127.0.0.1:8080/healthz
npm run test:server
```

`/healthz` 只报告组件状态，不返回密钥或 Worker 内部令牌。用户第一次调用项目 API 时才启动该项目的隔离 Worker；Gateway 只有在 Worker `/health` 返回合法 JSON，且 `connected=true`、`modelProvider.configured=true` 时才把它加入可用池。该检查能阻止空密钥或不支持的 provider 误报就绪，但不会向上游发起付费探针，因此无法证明错误密钥一定可调用。`MANJING_MAX_TENANT_WORKERS`、`MANJING_MAX_WORKERS_PER_USER` 和 `MANJING_WORKER_IDLE_TIMEOUT_MS` 控制容量。生产 `.env.server` 示例会在关机前最长等待活跃任务 15 分钟，Compose 的 stop grace 略长于该时间；付费任务运行时不要强制 `kill -9` 或缩短窗口。

租户 Bridge 收到 `SIGTERM` 后会停止接受新任务，等待 LibTV CLI 自身终态及其他活跃任务，不会为付费命令额外设置超时或自动重提。关机开始时的任务编号、远端 task id 和重试策略会原子写入项目的 `work/bridge-shutdown-state.json`，便于异常强制终止后人工核对。

当前实现适合单机／单节点、可控用户范围的运营。独立目录、进程和环境白名单用于防止误串数据，但同一容器中的 Worker 仍是同一 Linux UID，不能当作对恶意代码的强安全沙箱。面向完全不可信的公众租户时，需要进一步改为每租户容器／UID／网络和对象存储，并增加邮箱验证、套餐余额与总费用熔断。水平扩容前还需要共享会话库和粘性项目路由，不能让多个 Gateway 同时写同一 SQLite。

每次 Responses 调用会在对应 JSON 旁生成 `.usage.json`，可汇总 input/output token；GPT Image 结果的 usage 也会记账。LibTV 付费任务如果已经返回 task id，或提交后网络状态不明确，会标记为人工检查，禁止自动重复提交。

## 安全清单

- 密钥只放 `.env.server`、systemd credential 或云 Secret Manager；前端构建变量里不得放任何 API Key，也不要复制整份其他项目的环境文件。
- 公网只暴露 HTTPS 的 Nginx／负载均衡，不暴露 `3000`、`8080` 或租户 Worker 回环端口。
- 保持 Secure、HttpOnly、SameSite=Lax Cookie；不要打开 `MANJING_ALLOW_ORIGINLESS_MUTATIONS`。
- 注册接口已有 IP 级速率限制。正式公开注册前仍应接邮箱验证、找回密码、服务条款、风控／验证码与配额计费。
- 默认按 `Asia/Shanghai` 日历日限制普通用户 10 个、超级管理员 100 个 AI 模型调用预算单位（全服 200）、5 次 LibTV 登录请求（全服 100），上传 100 次且 1 GiB（全服 2000 次且 20 GiB）。超级管理员额度由 `MANJING_DAILY_SUPERADMIN_AI_REQUESTS` 单独控制，不改变普通用户上限，也仍受全服总额度约束。`MANJING_DAILY_AI_REQUESTS` 和 `MANJING_DAILY_GLOBAL_AI_REQUESTS` 的名字为历史兼容，当前表示保守的上游模型调用预算单位，不是 HTTP 请求数：视频 `media-analyze=2`；漫画 `media-analyze=6×ceil(页数/4)`，1/4/5/40 页分别预留 6/6/12/60；`manga-recut-boxes=2×ceil(页数/4)`，同样页数分别预留 2/2/4/20；`annotations=2`、`annotations-batch=10`、`complete-shot-prompt=2`、`review-shot-prompt=2`、`global-annotations=2`、`load-script=2`。漫画页数预算由网关解析 JSON 后动态预留，请求体会原样转发给租户 Worker；分析和重裁都要携带完整、不重复的 `mediaIds`，单次最多 40 页。全片批注单次最多 20 个 Shot：每 4 个一组，最多 5 组，每组首次生成加 1 次结构修复，因此最坏与 10 单位一致；网关和 Worker 都在启动模型任务前拒绝第 21 个 Shot。实际调用少于预估时也不会返还单位，以避免重试、修复调用和多阶段分析造成成本低估。40 页漫画分析需要至少 60 个用户和全局 AI 预算单位，否则网关会在调用 Worker 前拒绝。OpenAI 图片和 LibTV 付费生成默认为 `0`，未经运营显式开通会返回 `402`。这是安全上限，不是套餐计费系统；上线前按 API 预算调整用户与全局的 `MANJING_DAILY_*` 值。
- 每用户／项目的 LibTV 短信发送还有 Worker 内短周期节流：默认每 60 秒最多成功发送 1 次、15 分钟最多 5 次；可用 `MANJING_LIBTV_SMS_COOLDOWN_MS`、`MANJING_LIBTV_SMS_WINDOW_MS` 和 `MANJING_LIBTV_SMS_MAX_PER_WINDOW` 调整。未成功的 CAPTCHA 挑战不计为已发短信，允许携验证结果立即重试。
- 单个活跃项目当前对应一个 Node Worker。先用真实漫画压测内存，再调整 `MANJING_MAX_TENANT_WORKERS`。

## 当前不包含

- 原生 iOS/Android App、应用商店打包和系统推送。
- 邮箱验证、找回密码、管理员后台、套餐支付和发票。
- 多节点共享存储、Kubernetes HPA 和跨节点任务迁移。
- 已确认视频包的自动 LibTV 视频节点提交；当前 LibTV 已用于分镜图和资产图，视频包仍需按实时模型 schema 接线后再开放付费提交。
